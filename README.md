B 站互联网职业通识 20 讲：研发岗分类，前端后端测试岗位差异解析

很多同学想进互联网做研发，但一看到“前端、后端、测试”就发懵：都是写代码，到底差在哪？选错方向，入行后才发现每天干的事和想象不一样。这 20 讲里，研发岗分类是职业通识的第一课，核心不是背岗位名称，而是理解每个岗位解决什么问题、交付什么成果、和谁协作。把这三件事想清楚，方向就不会选偏。

一、研发岗不是只有“写代码”

互联网研发是一条链，不是一个人。产品提出需求，设计出交互，研发负责实现，测试负责验证，运维负责上线和稳定，数据负责度量效果。研发岗内部又分前端、后端、客户端、测试、算法、数据、运维等方向。不同岗位的代码量不同，但共同点是：都要把业务问题翻译成技术方案，都要对交付质量负责。选岗位不要只看“写不写代码”，而要看你想解决哪类问题、喜欢和什么打交道。

二、前端：离用户最近的那一层

前端负责用户能看到、能操作的部分。网页、H5、小程序、管理后台、可视化大屏，都是前端的战场。工作内容包括页面结构搭建、样式还原、交互逻辑、接口联调、性能优化和兼容性处理。前端的特点是“所见即所得”，改一行样式就能看到效果，反馈快，成就感直接。

前端要和设计师对还原度，和后端对接口，和产品对交互细节。核心能力是 HTML、CSS、JavaScript，加上框架生态、工程化工具和调试能力。前端不是“画页面”那么简单，复杂交互、状态管理、性能优化和跨端适配都很考验功底。适合对视觉和交互敏感、喜欢快速看到结果、愿意打磨细节的人。

三、后端：撑住业务的那一层

后端负责用户看不到但业务离不开的部分。接口设计、业务逻辑、数据存储、权限控制、并发处理、服务治理，都是后端的工作。前端发来请求，后端决定怎么处理、查什么数据、返回什么结果。后端的特点是“逻辑深、链路长”，一个需求往往牵涉数据库、缓存、消息队列和多个服务。

后端要和前端对接口，和产品对业务规则，和运维对部署，和测试对边界。核心能力是编程语言、数据结构、数据库、网络协议和系统设计。后端不是“增删改查”那么简单，高并发、一致性、故障恢复和成本控制都是硬功夫。适合喜欢琢磨逻辑、对系统和数据敏感、能承受复杂问题拆解的人。

四、测试：守住质量的那一层

测试负责验证做出来的东西对不对、稳不稳、好不好用。功能测试、接口测试、性能测试、自动化测试、安全测试，都是测试的范畴。测试不是“点点点”，而是设计用例、构造数据、复现问题、推动修复。测试要懂业务，也要懂技术，能写自动化脚本、搭测试环境、分析日志和定位缺陷。

测试要和产品对验收标准，和研发对缺陷，和运维对线上问题。核心能力是测试设计、缺陷管理、自动化工具和一定的编码能力。测试的价值不是“找茬”，而是让问题在用户之前被发现。适合细心、有怀疑精神、喜欢从全局看质量的人。

五、怎么选：看问题类型，也看协作偏好

选岗位可以问自己三个问题。第一，你喜欢解决哪类问题：视觉交互、业务逻辑，还是质量验证？第二，你喜欢和谁打交道：设计师和用户、产品和数据，还是研发和运维？第三，你享受哪种反馈节奏：改完立刻看到效果，还是逻辑跑通后的踏实感，还是问题被复现和修复的确定感？

前端反馈快、视觉感强；后端逻辑深、系统性强；测试视角全、质量感强。三个岗位没有高低，只有匹配。入门阶段可以先学基础，再通过小项目体验真实工作流：做一个页面、写一个接口、设计一组用例，做完就知道自己更喜欢哪一段。

研发岗分类的通识心法是：前端管“看得见”，后端管“撑得住”，测试管“守得牢”。理解岗位差异，不是为了贴标签，而是为了找到自己能长期投入的方向。选对了，成长才不拧巴。
